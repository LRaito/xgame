# make-guide：把攻略素材做成可导入的中文攻略

本平台的「攻略」可以是挂在某个游戏卡带下的一整套**静态网页**（也支持直接传 PDF）：静态网页的
交付形态是一个 **zip 包**（本地按 `<平台简称>_<中文游戏名>.zip` 命名，上传后平台统一存为
数据根下的 `game/{游戏类型}/{卡带ID}/guide.zip`），包内入口固定是
**根目录的 `index.html`**，在游戏管理页的编辑弹框里用「上传攻略」上传。包整个套一层顶层目录会自动剥掉
（右键「压缩」出来的包必然是这种形态）。
它没有文件清单表；攻略形态记在库里的 `games.guide_kind`（`''`/`zip`/`pdf`），上传写值、删除清空；
查看时才把包解到运行时根（`game/{游戏类型}/{卡带ID}/guide/`，下次直接复用），读取走
`GET /api/games/{id}/guide/{路径}`（**需登录**），在游戏中心右键「攻略」用新标签页顶层打开。

本技能把**现成的攻略素材**变成这样一个目录，输入有两类：

- **静态 HTML 攻略站**：镜像下来、剥壳、翻译。
- **PDF / 扫描说明书 / 攻略本**：先交给 MinerU 解析成 JSON + Markdown + 图片，再按「MinerU 路线」整理。
  如果只想原样提供 PDF，直接在编辑弹框上传 PDF 即可（`guide_kind='pdf'`），不必做静态站。

做法来自两次真实转换：`https://www.imasaragame.com/yugiohmcgb/`（日文，GBC《游戏王 怪兽胶囊》）
→ 174 个页面、438 个文件、1.6MB；以及 1987 年美版《塞尔达传说》说明书的 MinerU 解析产物
→ 9 个内容页、78 张图、1.1MB（`FC_塞尔达传说.zip`）。成品长这样：

```
guide/                 ← 成品目录（打包后就是 zip 的根）
├── index.html         ← 必须有；目录页 + 游戏资料表 + 出处
├── pages/             ← 内容页（静态站保留原站子目录层级；MinerU 路线按章节分页）
└── assets/
    ├── css/site.css   ← 静态站合并原站样式；MinerU 路线自建一份中文优先的样式
    ├── fonts/         ← 图标字体（静态站原样拷贝；没有就省略）
    └── images/        ← 图片（静态站按原目录；MinerU 路线把 image_path 全部下载到本地）
```

三条原则，冲突时按这个顺序取舍：

1. **只留攻略本身**——广告、脚本、站内搜索、站点级导航、版权页脚、外链全部删掉；
   扫描件里的保修、FCC、出版信息、封底同样剔除。
2. **版式跟素材一致**——静态站保留原站的 DOM 结构与 class、照搬它的样式表，不要重新设计；
   PDF / MinerU 路线没有原页可抄，就自建一套中文优先、移动端友好的版式，但章节顺序与图文关系仍按原书。
3. **正文转中文，专有名词保留原文**——只在**标题/词条位置**写 `中文（原文）`
   （`装甲蜥蜴（アーマーリザード）`），正文与数据表格里只写中文 `装甲蜥蜴`。

抓站或转换扫描件之前，先看素材的版权声明（范例站写明「無断転載を禁じます」）。本技能是给**个人自用**的：
只往自己的平台上放，**首页 footer 必须写出处**。

## 输入源与路线选择

| 手上有什么 | 走哪条路 |
|---|---|
| 静态 HTML 攻略站 | 「流程」+「保留 / 删除对照表」 |
| PDF / 扫描说明书 / 攻略本 | 先 MinerU 解析 →「MinerU 路线」；只要原样 PDF 就直接上传 PDF |
| 已整理好的中文 HTML 目录 | 直接按「平台侧的硬约束」自检、命名、打包 |
| 只有 Markdown、没有 JSON/图片 | 可以不追 JSON，但丢失的图片和页脚提示要自己补——见「MinerU 路线」的坑 |

## 平台侧的硬约束（导入前逐条核对）

| 约束 | 值 | 越界会怎样 |
|---|---|---|
| 入口 | **根目录**的 `index.html`（大小写不敏感，落盘统一小写；`index.htm` 不认，子目录里的不算） | 400「攻略根目录需包含 index.html。」 |
| 条目数 | 解压后 ≤ 2000（与 H5 共用 `archive.MAX_ENTRIES`） | 400 |
| zip 本体 | ≤ 128MB（应用层上限；nginx 网关已放宽到 512m，给 NDS 本体留余量） | 400 / 413 |
| 单个文件 | 解压后 ≤ 64MB | 400 |
| 总体积 | 解压后 ≤ 256MB | 400 |
| 压缩比 | > 200 且解压后 > 1MB 视为异常 | 400 |
| 路径 | 禁 `\`、`?`、`#`、`%`、控制字符、`:*?"<>|`、绝对路径、`.`/`..` 段、以点或空格结尾的段、Windows 保留设备名（`CON`/`NUL`/`COM1`…）；相对路径 ≤ 512 字符、≤ 32 段 | 400 |
| 重名 | 大小写不敏感（`Index.html` 与 `index.html` 冲突） | 400 |
| 链接 | **一律相对路径**。攻略在 `/api/games/{id}/guide/` 前缀下顶层打开，`/xxx` 这种绝对路径会指到站点根、必然 404 | 页面 404/白屏 |

### 压缩包命名

成品 zip 统一命名 **`<平台简称>_<中文游戏名>.zip`**。既有交付包的命名见 `~/code/guide-zips/`
（`GB_大金刚.zip`、`GBC_游戏王 - 怪兽胶囊.zip`、`GBA_马里奥VS大金刚.zip`、
`SFC_超级马里奥世界2-耀西岛.zip`）。

- 平台简称用机种通用写法：`GB`、`GBC`、`GBA`、`N64`、`SFC`、`FC`。不要写成 `nes`、`snes`
  这类小写 game_type。
- 中文游戏名取攻略标题里的游戏名，去掉 `【攻略】` 前缀；副标题用 ` - ` 连接
  （`GBC_游戏王 - 怪兽胶囊.zip`），系列编号紧跟名字（`GB_超级中国人2.zip`）。
- 命名只影响交付文件本身；zip 内部入口仍固定为根目录的 `index.html`。
- 同一游戏重做时沿用已有包名覆盖，不要另起名字。

**导入**：把成品目录打成 zip 并按上一节命名（Windows：右键 `guide` 文件夹 → 压缩，再把生成的
`guide.zip` 改成 `<平台简称>_<中文游戏名>.zip`；命令行：
`cd <父目录> && zip -r "FC_塞尔达传说.zip" guide`）→ 游戏管理页 → 该游戏「编辑」→
「游戏攻略」→「上传攻略」→ 保存（重传整体替换旧攻略）。
**打断言**：`python .claude/skills/make-guide/check_guide.py <目录>` 先跑一遍，
它校验的是解压后的目录，打包前后都适用。
**验证**：游戏中心右键卡片 →「攻略」（**没有攻略就不显示这一项**）→ 新标签页打开，
点几个内部链接、看图片和样式。

## 流程（静态 HTML 攻略站）

1. **定游戏与标题。** 拿到卡带ID、游戏类型、游戏中文名；攻略标题统一 `【攻略】<游戏中文名>`。
2. **找原站（静态站路线）。** 搜「<游戏名> 攻略 / walkthrough / 攻略チャート」。合格标准：正文是**静态 HTML**
   （不是 JS 渲染出来的）、有目录或分页、结构清晰（分层导航 + 表格 + 图片）。
   如果只找到 PDF、扫描说明书或攻略本，改走「MinerU 路线」。
3. **完整镜像。** `wget --mirror --page-requisites --convert-links` 或逐页 `curl`，
   图片/CSS/字体一并抓；控制频率、看 robots.txt。**记下出处 URL**（首页要用）。
4. **目录规划。** 按开篇那个结构摆：根只留 `index.html`，原站内容页整棵收进 `pages/`，
   图片/CSS/字体收进 `assets/images|css|fonts/`。原站子目录层级照搬，别拍平（免得同名文件打架）。
5. **剥站点外壳。** 照下面的对照表删。
6. **重写链接。** 所有 `href`/`src` 改成**按当前文件深度正确的相对路径**：`pages/mc/x.html` 里指向
   `pages/c/1.html` 要写 `../c/1.html`，`pages/x.html` 里写 `c/1.html`，根 `index.html` 里写
   `pages/c/1.html`。原站侧栏里那种 `/yugiohmcgb/c/1.html` 绝对链接**必须改**。改完逐个点一遍。
7. **翻译。** 先列**术语表**（怪物名/道具名/地名/系统词，原文与中文对照）——**写在 guide 目录之外**
   （如 `/tmp/<游戏>-术语表.md`），目录里每个文件都占条目数的上限。然后逐页翻，术语表照着填。
8. **补外壳。** `<html lang="zh-CN">`、charset、viewport、`<title>`（见下）、首页 footer 写出处。
9. **自检。** `python3 .claude/skills/make-guide/check_guide.py <攻略目录>`：error 清零、
   warning 逐条确认。
10. **精简（视情况，见下节）。** 同类详情页逐页重复同一份大纲索引时，只留 `index.html` 那一份，
    详情页删掉冗余块。
11. **打包并命名。** 按 `<平台简称>_<中文游戏名>.zip` 命名（见「压缩包命名」）。
12. **导入并验证**（见上面的导入步骤）。

### 精简：详情页里重复的大纲索引

翻译完先别急着打包，看一眼详情页——这类站常把「整站/整类目大纲」复制进每一页的正文，
几十上百个详情页各扛一份，是体积的主要来源，也纯属导航冗余。**判据、做法和边界如下，
不满足就别动**（脚本不检查这一类冗余，得人工判断）。

**什么时候精简**

- 同一类的详情页里，正文区有一整块**纯跳转清单**（`<ul>`/`<ol>`/表格/`<nav>`），
  列出大量其它页面的链接，且这份清单在**多数同类页面**上逐字重复
  （典型：每只宝可梦的详情页都带着整份图鉴大纲；每张卡的页面都带着整份卡表链接）。
- 它与 `index.html` 或某个公共索引页的大纲基本重合，删掉不影响读懂这一页。
- 数量级上才值得做：清单被复制了几十个页面。只有一两页重复、或精简后省不下多少，就别改。

**怎么删**

- **`index.html` 是保留大纲索引的地方**。原站另有专门承担索引的公共页（如 `pages/list.html`）时，
  那一页也留着——它自己就是大纲；除此之外的详情页一律只留本页内容。
- 详情页把那一整块**连容器一起删**（`<ul>` 连同它前面的小标题、外层 `<div>`/`<section>`），
  **别留空壳**；容器在 CSS 里有专用样式且只服务这一块的，可选一并删掉规则。
- 只删**跳转清单**：正文、表格、图片、本页自己的数据与说明文字一律保留。清单里若混着本页专属
  信息（条目数值、说明列），这一块就不算冗余，**整块留下**。拿不准时按「不删」处理。
- 删完重跑 `check_guide.py`：error 必须照旧为 0（重点看断链），再抽 2–3 个详情页打开确认版式没塌。
- 把精简前后的**页数 / 文件数 / 体积**记进进度文件的一节「精简」；不满足条件就写一句
  「无重复索引，未精简」。

**边界：这些不算冗余，别顺手删**

- 侧栏的攻略内导航（`#accordion` 之类每页都有的章节入口）——它是站内导航骨架，本技能要求每页都有；
  只有它被扩成整站全量条目清单时，才按上面的判据处理。
- 面包屑、页脚的上一页/下一页、详情页里的前后篇链接、首页 `index.html` 自己的大纲。
- 平台要求保留的内容结构（表格、图片、`section` 层次）不在精简范围内。

### 保留 / 删除对照表

| 原站的东西 | 怎么处理 |
|---|---|
| `<script>`（jQuery、统计、广告） | **全删**。范例成品里一个 script 都没有 |
| 广告位（`<ins class="adsbygoogle">`、`.adspace`） | 删 |
| 站内搜索框（`<form id="search-box">`） | 删 |
| Amazon 推荐 `<iframe>`、任何 `<form>` | 删 |
| 站点级侧栏菜单（关于本站/链接集/邮件表单等外链） | 删，整段 `<ul>` 一起删，**别留空壳** |
| 页脚站点声明、Copyright 行、返回顶部、语言切换 | 删 |
| 页脚「回总站首页」（`tohome`） | 删 |
| 一切外链（`http(s)://`、`//`） | 删，或退化成纯文本；攻略里不该有外链 |
| 内容结构 `article/#main/#content/#inner/section/h1–h4/表格/图片` | **原样保留**，class 也保留 |
| 面包屑 `#bread` | 保留并翻译（`ホーム` → `首页`） |
| 页脚上一页/下一页导航 | 保留并翻译 |
| 侧栏里的攻略内导航（各章节入口） | 保留并翻译；**每页都要有**，链接按深度改写（它被扩成整站全量条目清单时，按后面「精简」一节处理） |
| 详情页正文里重复的大纲索引（每页都抄一份整类目/整站链接） | `index.html` 留一份，详情页**连容器删掉**——见「精简：详情页里重复的大纲索引」 |
| header 的 logo 图片链接 | 换成文字标题链接 `【攻略】<游戏中文名>` |
| 图片 | 原样拷贝，不重采样、不改格式、不压缩，只改路径；`alt` 一并翻译 |
| 样式表 | 原站多个 CSS 合并成一个 `assets/css/site.css`，删掉上面被删元素的选择器；字体栈换中文优先 |

### `<title>` 规则

- 首页：`【攻略】游戏王：怪兽胶囊`
- 子页：`<页名> - 【攻略】游戏王：怪兽胶囊`
- 列表/详情页带中间层：`装甲蜥蜴（アーマーリザード） - 怪兽胶囊一览 - 【攻略】游戏王：怪兽胶囊`

### 翻译时原样保留的东西

数字、等级、概率、表格结构一律不动；`Game Over`、`HP/AT/DF/SP`、`LV`、键位名，
以及本来就是英文/片假名的专有名词（按术语表定名，别半译）。

## MinerU 路线：PDF / 扫描件 / 说明书

MinerU 解析后通常得到三样东西：`xxx.json`（布局、bbox、块类型）、`xxx.md`（可读文本）、
图片（本地目录或远程 CDN 链接）。**优先用 JSON，Markdown 只作交叉校验**——JSON 保留页号、
bbox 与 `discarded_blocks`，Markdown 会丢页脚提示、压平标题、把图注变成无归属的文本行。

不同 MinerU 版本或导出方式的文件名/字段会略有差异（常见还有 `content_list.json`、`middle.json`、
`full.md` + `images/`）。先看顶层结构再写解析：如果拿到的是带 `images/` 的包，直接用本地图，
跳过下载；如果 `image_path` 是远程 URL，就必须下载（见步骤 4）。

**先认 JSON 的结构：**

```
pdf_info[]                      ← 一页扫描纸一项
├── page_idx / page_size
├── para_blocks[]               ← 正文块
│   ├── {type:"text"|"title", bbox, level?, lines[].spans[].content}
│   └── {type:"image", bbox, blocks[]}
│       ├── image_body     → lines[].spans[].image_path
│       └── image_footnote → 图注文本
└── discarded_blocks[]          ← 页眉/页脚/页码，可能混有真实正文
```

### 步骤

1. **抽取规范化块。** 给每块生成稳定 id（如 `p15b05`）；文本块拼接 `lines[].spans[].content`，
   标题块记 `level`；图片块取 `image_path` 与 `image_footnote`；跳过空块。对块数与类型统计做断言。
2. **回收 discarded_blocks。** MinerU 常把说明书页脚的边注/提示判成 `footer`/`page_footnote`。
   过滤页码、页眉和来源水印（如 Vimm）后，把剩下的正文回收成「原书边注」，放到对应小节末尾。
   **不要省这一步**——范例的 25 页扫描里丢了 22 条提示。
3. **判版式。** `page_size` 是扫描纸尺寸；一张纸常含左右两页，按块中心 x 与 `page_size[0]/2`
   分左右页。多栏页面上 MinerU 的块顺序大体可用，但图片会集中前置、句子会跨栏断开，
   要按 bbox 相邻关系与上下文人工缝合（范例里加农提示的续句跑到了几页之后）。
4. **图片本地化。** `image_path` 常是远程 CDN（如 `cdn-mineru.openxlab.org.cn`）。全部下载到
   `assets/images/`，校验 JPEG/PNG 魔数与实际宽高，失败就停；成品里**绝不能留 CDN 链接**。
   CDN 图通常已按 bbox 裁好，不需要再裁。
5. **重建标题层级。** MinerU 常把全书标题压成同一级（范例：113 个标题里 111 个是 level 2）。
   按「章 / 节 / 条目」重新定级：页面 h1 用重排后的页名，散文小节 h2，怪物/道具/步骤 h3。
   同名标题可能属于不同章（如两处 The Overworld），按块 id 定角色，不要按文本猜。
6. **OCR 校正。** 扫描件的拼写错误按上下文修正并记下来（范例：Brawing→Braving、
   benchmen→henchmen、Manhandia→Manhandla、Leavers→Leevers）。数字、键位、屏幕原文不要改。
7. **翻译、组页、打包。** 与静态站路线相同：术语表放 guide 目录之外，`中文（原文）` 只在词条位置；
   首页 footer 写出处；按 `<平台简称>_<中文游戏名>.zip` 命名。

`data/glossary.tsv` 是术语表。全部只用 Python 标准库，可直接借鉴或另写。

### MinerU 路线特有的坑

- **只信 Markdown 会丢内容**：`discarded_blocks` 里的正文和 `image_footnote` 里的图注都不在 Markdown 里。
- **图片是外链**：不下载就导入，平台里图全裂；下载后忘了改相对路径，又会 404。
- **双页扫描**：直接按 Markdown 顺序读，会把左右两页的内容交错。
- **标题全平**：不能按 `level` 直接生成目录，要人工定角色表。
- **图注藏在图片块里**：`image_footnote` 不在正文块里，容易漏。
- **OCR 噪声**：错拼会原样进入译文，翻译时按上下文校正，不要逐词直译。
- **表格/公式可能没有块**：攻略不需要公式；遇到表格先用 Markdown 表格或 `<table>` 复刻，别丢数据。

**共用规则**：`<title>`、翻译与专有名词写法见上面的同名小节；「精简」与「保留/删除对照表」只适用于静态站路线——MinerU 路线没有原站外壳可剥，也不需要处理详情页重复索引。

## 常见坑（这两次转换里真出现过）

- **`<meta name="description">` 整份留着原语言**——当年的范例里 174 个页面全是日文。它也算可见文本
  （搜索结果、分享预览），必须一起翻。
- **复合词半译**——`隠しカプセルマシン` 被译成 `隠し胶囊机`（4 个文件）。术语表要收**复合词**，
  不能只收单词。
- **`alt` 没翻**——`alt="ザンキ"` 留了 2 处。`alt`、`title` 属性都算可见文本。
- **留空壳容器**——首页侧栏删完菜单后剩了个 `<aside class="side">` 套空 `<ul></ul>`。删就删干净。
- **CSS 里留外文和死规则**——当年的范例 `site.css` 还留着 `content: "▼クリックで等倍表示"` 与
  `#help-popup`/`#copyright` 这些用不到的规则；字体栈也还是 `Yu Gothic/メイリオ`。
- **图片多的站会撞 2000 条目的上限**——只留攻略真正用得到的图（这本来就是原则一）。

## 用法

```bash
python3 .claude/skills/make-guide/check_guide.py [攻略目录] [--quiet]
```

- `<攻略目录>`：要交付的攻略根目录（含 `index.html` 那一层），默认当前目录。
- `--quiet`：只打印结论与 error，不列 warning 明细。

输出是中文报告，分「错误 / 警告 / 统计」三段；**有 error 时退出码 1**，只有 warning 时退出码 0。
它只读，不写任何文件，可以随便反复跑。

## 依赖

只用 Python 标准库（`html.parser` + `pathlib`），**不引入任何第三方包**，也**不在**
`requirements.txt` 里（后端运行不需要它）。

## 排错

- **脚本报 error**：先修 error（平台会直接拒），再看 warning。error 分三类——外壳没剥干净
  （script/iframe/form/外链/绝对链接）、路径或数量越界、页面本身坏了（断链、缺 charset、`lang` 不对）。
- **导入报 400**：对照上面「硬约束」表，中文消息会指出是哪条（缺 `index.html`、重名、路径非法、超限）。
- **导入成功但打开是空白/没样式**：多半是绝对链接或漏抓资源——脚本的断链与绝对链接检查就是查这个。
- **右键菜单里没有「攻略」**：`has_guide` 来自 `games.guide_kind`，说明上传没有成功
  （没上传、上传被拒，或保存失败）；上传成功后这一列才会置位。
- **打开攻略 400**：包在数据根里但解不开（被手改坏了、或不是合法 zip），后端会再校验一次。
- **中文显示怪/字形不对**：CSS 字体栈还在用日文字体，换成中文优先
  （`"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`）。

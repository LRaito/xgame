# make-guide：把攻略素材做成可导入的中文攻略

本平台的「攻略」是挂在某个游戏卡带下的一整套静态网页，也支持直接传 PDF。

- 静态网页的交付形态是一个 zip 包。
- 包内入口固定是**根目录的 `index.html`**。
- 整个包套一层顶层目录会自动剥掉。
- 上传入口：游戏管理页的编辑弹框 →「上传攻略」。
- 平台侧的包契约、上限与读取接口见
  [`docs/specs/guide-and-h5.md`](../../../docs/specs/guide-and-h5.md)。

本技能把**现成的攻略素材**变成这样一个目录，输入有两类：

- **静态 HTML 攻略站**：镜像下来、剥壳、翻译。
- **PDF / 扫描说明书 / 攻略本**：
  - 先交给 MinerU 解析成 JSON + Markdown + 图片，再按「MinerU 路线」整理。
  - 只想原样提供 PDF，直接在编辑弹框上传 PDF 即可，不必做静态站。

成品结构：

```
guide/                 ← 成品目录（打包后就是 zip 的根）
├── index.html         ← 必须有；目录页 + 游戏资料表 + 出处
├── pages/             ← 内容页
└── assets/
    ├── css/site.css   ← 样式
    ├── fonts/         ← 图标字体（没有就省略）
    └── images/        ← 图片
```

三条原则，冲突时按这个顺序取舍：

1. **只留攻略本身。**
   广告、脚本、站内搜索、站点级导航、版权页脚、外链全部删掉。
   扫描件里的保修、FCC、出版信息、封底同样剔除。
2. **版式跟素材一致。**
   - 静态站保留原站 DOM 与 class，照搬样式表，不重新设计。
   - PDF / MinerU 路线自建中文优先、移动端友好的版式。
   - 章节顺序与图文关系仍按原书。
3. **正文转中文，专有名词保留原文。**
   - 只在**标题/词条位置**写 `中文（原文）`，如 `装甲蜥蜴（アーマーリザード）`。
   - 正文与数据表格里只写中文 `装甲蜥蜴`。

抓站或转换扫描件之前，先看素材的版权声明。
本技能是给**个人自用**的：只往自己的平台上放，**首页 footer 必须写出处**。

## 输入源与路线选择

| 手上有什么 | 走哪条路 |
|---|---|
| 静态 HTML 攻略站 | 「流程」+「保留 / 删除对照表」 |
| PDF / 扫描说明书 / 攻略本 | 先 MinerU 解析 →「MinerU 路线」 |
| 已整理好的中文 HTML 目录 | 按「平台侧硬约束」自检、命名、打包 |
| 只有 Markdown、没有 JSON/图片 | 可走 MinerU 路线，但要自己补图片与页脚提示 |

## 平台侧硬约束（导入前逐条核对）

- **入口**：根目录的 `index.html`。
  - 大小写不敏感，落盘统一小写。
  - `index.htm` 不认，子目录里的不算。
- **链接**：一律相对路径。
  - 攻略在 `/api/games/{id}/guide/` 前缀下打开。
  - `/xxx` 这种绝对路径会指到站点根，必然 404。
- **条目数**：解压后 ≤ 2000。
- **zip 本体**：≤ 128MB。
- 其余上限与路径/重名规则见
  [`docs/specs/guide-and-h5.md`](../../../docs/specs/guide-and-h5.md)：
  单条 ≤64MB、总量 ≤256MB、压缩比 ≤200、路径与重名限制。

### 压缩包命名

成品 zip 统一命名 **`<平台简称>_<中文游戏名>.zip`**。

- 平台简称用机种通用写法：`GB`、`GBC`、`GBA`、`N64`、`SFC`、`FC`。
  不要写成 `nes`、`snes` 这类小写 game_type。
- 中文游戏名取攻略标题里的游戏名，去掉 `【攻略】` 前缀。
- 副标题用 ` - ` 连接，系列编号紧跟名字。
- 命名只影响交付文件；zip 内部入口仍是根目录 `index.html`。
- 同一游戏重做时沿用已有包名覆盖。

**导入**：

1. 把成品目录打成 zip 并按上节命名。
   - Windows：右键 `guide` 文件夹 → 压缩，再把 `guide.zip` 改成目标名。
   - 命令行：`cd <父目录> && zip -r "FC_塞尔达传说.zip" guide`。
2. 游戏管理页 → 该游戏「编辑」→「游戏攻略」→「上传攻略」→ 保存。
   重传会整体替换旧攻略。

**自检**：

```bash
python3 .claude/skills/make-guide/check_guide.py <目录>
```

- 校验解压后的目录，打包前后都适用。
- error 必须清零，warning 逐条确认。

**验证**：

- 游戏中心右键卡片 →「攻略」→ 新标签页打开。
- 点几个内部链接，看图片与样式。

## 流程（静态 HTML 攻略站）

1. **定游戏与标题。** 拿到卡带 ID、游戏类型、游戏中文名；标题统一 `【攻略】<游戏中文名>`。
2. **找原站。** 搜「<游戏名> 攻略 / walkthrough / 攻略チャート」。
   - 合格标准：正文是静态 HTML、有目录或分页、结构清晰。
   - 只找到 PDF / 扫描件时，改走「MinerU 路线」。
3. **完整镜像。** 用 `wget --mirror --page-requisites --convert-links` 或逐页 `curl`。
   - 图片 / CSS / 字体一并抓。
   - 控制频率、看 robots.txt。
   - **记下出处 URL**。
4. **目录规划。**
   - 根只留 `index.html`。
   - 原站内容页整棵收进 `pages/`。
   - 图片 / CSS / 字体收进 `assets/`。
   - 原站子目录层级照搬，别拍平。
5. **剥站点外壳。** 照「保留 / 删除对照表」删。
6. **重写链接。** 所有 `href` / `src` 改成按当前文件深度正确的相对路径。
   - `pages/mc/x.html` 指向 `pages/c/1.html` 时写 `../c/1.html`。
   - 根 `index.html` 里写 `pages/c/1.html`。
   - 原站侧栏的 `/yugiohmcgb/c/1.html` 绝对链接必须改。
   - 改完逐个点一遍。
7. **翻译。**
   - 先列术语表（怪物名 / 道具名 / 地名 / 系统词）。
   - 术语表写在 guide 目录之外（如 `/tmp/<游戏>-术语表.md`）。
   - 逐页翻，术语表照着填。
8. **补外壳。**
   - `<html lang="zh-CN">`、charset、viewport。
   - `<title>` 按下面规则。
   - 首页 footer 写出处。
9. **自检。** 跑 `check_guide.py`：error 清零，warning 逐条确认。
10. **精简（视情况）。** 同类详情页重复同一份大纲索引时，只留 `index.html` 那一份。
11. **打包并命名。**
12. **导入并验证。**

### 精简：详情页里重复的大纲索引

翻译完先别急着打包，看一眼详情页。
这类站常把「整站/整类目大纲」复制进每一页，是体积的主要来源，也是导航冗余。

**什么时候精简**

- 同一类详情页里，正文区有一整块**纯跳转清单**。
- 清单在多数同类页面上逐字重复。
- 它与 `index.html` 或公共索引页的大纲基本重合。
- 只有复制了几十个页面才值得做；一两页就别改。

**怎么删**

- `index.html` 是保留大纲索引的地方。
- 原站另有专门承担索引的公共页时，那一页也留着。
- 其余详情页只留本页内容：
  - 把那一整块**连容器一起删**。
  - 别留空壳。
  - 只服务这一块的 CSS 规则可一并删。
- 只删跳转清单：正文、表格、图片、本页数据一律保留。
- 清单里混着本页专属信息时，整块留下；拿不准就不删。
- 删完重跑 `check_guide.py`，再抽 2–3 个详情页确认版式没塌。
- 把精简前后的页数 / 文件数 / 体积记进进度文件。

**这些不算冗余，别顺手删**

- 侧栏的攻略内导航。
- 面包屑、上一页/下一页、前后篇链接。
- 首页自己的大纲。
- 平台要求保留的表格、图片与 `section` 层次。

### 保留 / 删除对照表

| 原站的东西 | 怎么处理 |
|---|---|
| `<script>`（jQuery、统计、广告） | 全删 |
| 广告位 | 删 |
| 站内搜索框 | 删 |
| Amazon 推荐 `<iframe>`、任何 `<form>` | 删 |
| 站点级侧栏菜单 | 整段删，别留空壳 |
| 页脚站点声明、Copyright、返回顶部、语言切换 | 删 |
| 页脚「回总站首页」 | 删 |
| 一切外链 | 删，或退化成纯文本 |
| 内容结构 `article/#main/#content/section/h1–h4/表格/图片` | 原样保留，class 也保留 |
| 面包屑 `#bread` | 保留并翻译 |
| 页脚上一页/下一页导航 | 保留并翻译 |
| 侧栏攻略内导航 | 保留并翻译，每页都要有 |
| 详情页里重复的大纲索引 | `index.html` 留一份，其余连容器删 |
| header 的 logo 图片链接 | 换成文字标题链接 |
| 图片 | 原样拷贝，只改路径；`alt` 一并翻译 |
| 样式表 | 合并成一个 `site.css`，字体栈换中文优先 |

### `<title>` 规则

- 首页：`【攻略】游戏王：怪兽胶囊`
- 子页：`<页名> - 【攻略】游戏王：怪兽胶囊`
- 带中间层：`装甲蜥蜴（アーマーリザード） - 怪兽胶囊一览 - 【攻略】游戏王：怪兽胶囊`

### 翻译时原样保留的东西

- 数字、等级、概率、表格结构。
- `Game Over`、`HP/AT/DF/SP`、`LV`、键位名。
- 本来就是英文或片假名的专有名词（按术语表定名，别半译）。

## MinerU 路线：PDF / 扫描件 / 说明书

MinerU 通常产出三样东西：

- `xxx.json`：布局、bbox、块类型。
- `xxx.md`：可读文本。
- 图片：本地目录或远程 CDN 链接。

**优先用 JSON，Markdown 只作交叉校验。**
JSON 保留页号、bbox 与 `discarded_blocks`；Markdown 会丢页脚提示、压平标题。

不同版本的文件名与字段会略有差异，先看顶层结构再写解析。

**JSON 结构：**

```
pdf_info[]                      ← 一页扫描纸一项
├── page_idx / page_size
├── para_blocks[]               ← 正文块
│   ├── {type:"text"|"title", bbox, level?, lines[].spans[].content}
│   └── {type:"image", bbox, blocks[]}
│       ├── image_body     → lines[].spans[].image_path
│       └── image_footnote → 图注文本
└── discarded_blocks[]          ← 页眉/页脚/页码
```

### 步骤

1. **抽取规范化块。**
   - 给每块生成稳定 id（如 `p15b05`）。
   - 文本块拼接 `lines[].spans[].content`。
   - 标题块记 `level`。
   - 图片块取 `image_path` 与 `image_footnote`。
   - 跳过空块，统计块数与类型。
2. **回收 `discarded_blocks`。**
   - MinerU 常把页脚边注判成 footer。
   - 过滤页码、页眉、来源水印后，把正文回收成「原书边注」。
   - 不要省这一步。
3. **判版式。**
   - `page_size` 是扫描纸尺寸。
   - 一张纸常含左右两页，按块中心 x 与 `page_size[0]/2` 分左右。
   - 多栏页面要按 bbox 与上下文人工缝合。
4. **图片本地化。**
   - `image_path` 常是远程 CDN。
   - 全部下载到 `assets/images/`。
   - 校验 JPEG/PNG 魔数与宽高，失败就停。
   - 成品里绝不能留 CDN 链接。
   - CDN 图通常已按 bbox 裁好，不需要再裁。
5. **重建标题层级。**
   - MinerU 常把全书标题压成同一级。
   - 按「章 / 节 / 条目」重新定级。
   - 同名标题可能属于不同章，按块 id 定角色，不要按文本猜。
6. **OCR 校正。**
   - 按上下文修正拼写错误并记下来。
   - 数字、键位、屏幕原文不要改。
7. **翻译、组页、打包。**
   - 与静态站路线相同。
   - 术语表放 guide 目录之外。
   - `中文（原文）` 只在词条位置。
   - 首页 footer 写出处。

### 参考实现

- 不随仓库提交，仅作示例。
- `scripts/extract.py`：JSON → 块。

- 全部只用 Python 标准库，可借鉴或另写。

### MinerU 路线特有的坑

- **只信 Markdown 会丢内容**：`discarded_blocks` 里的正文与 `image_footnote` 不在 Markdown 里。
- **图片是外链**：不下载就导入，图全裂；下载后忘改相对路径，又会 404。
- **双页扫描**：按 Markdown 顺序读会把左右页内容交错。
- **标题全平**：不能按 `level` 直接生成目录，要人工定角色表。
- **图注藏在图片块里**：`image_footnote` 不在正文块里。
- **OCR 噪声**：错拼会进入译文，按上下文校正。
- **表格/公式可能没有块**：表格用 Markdown 或 `<table>` 复刻，别丢数据。

**共用规则**：`<title>`、翻译与专有名词写法见上面的同名小节。
「精简」与「保留/删除对照表」只适用于静态站路线。

## 常见坑（真实转换里出现过）

- **`<meta name="description">` 留着原语言**：它也算可见文本，必须一起翻。
- **复合词半译**：术语表要收复合词，不能只收单词。
- **`alt` 没翻**：`alt`、`title` 属性都算可见文本。
- **留空壳容器**：删完菜单剩个空 `<aside>` / `<ul>`，删就删干净。
- **CSS 里留外文和死规则**：字体栈与用不到的规则要一起清。
- **图片多的站会撞 2000 条目上限**：只留攻略真正用得到的图。

## 用法

```bash
python3 .claude/skills/make-guide/check_guide.py [攻略目录] [--quiet]
```

- `<攻略目录>`：含 `index.html` 那一层，默认当前目录。
- `--quiet`：只打印结论与 error，不列 warning 明细。

输出是中文报告，分「错误 / 警告 / 统计」三段。
有 error 时退出码 1，只有 warning 时退出码 0。
它只读，不写文件，可反复跑。

## 依赖

只用 Python 标准库（`html.parser` + `pathlib`）。

- 不引入第三方包。
- 不在 `requirements.txt` 里（后端运行不需要）。

## 排错

- **脚本报 error**：先修 error（平台会直接拒），再看 warning。
  - 外壳没剥干净：script / iframe / form / 外链 / 绝对链接。
  - 路径或数量越界。
  - 页面本身坏了：断链、缺 charset、`lang` 不对。
- **导入报 400**：对照「平台侧硬约束」，中文消息会指出是哪条。
- **导入成功但打开空白 / 没样式**：多半是绝对链接或漏抓资源。
- **右键菜单里没有「攻略」**：`guide_kind` 没置位，说明上传没有成功。
- **打开攻略 400**：包在数据根里但解不开，后端会再校验一次。
- **中文显示怪**：CSS 字体栈还在用日文字体，换成中文优先：
  `"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`

# make-guide：把网上攻略做成可导入的中文攻略

本平台的「攻略」是挂在某个游戏卡带下的一整套**静态网页**：交付形态是一个 **zip 包**
（数据根下的 `game/{游戏类型}/{卡带ID}/guide.zip`），包内入口固定是**根目录的 `index.html`**，
在游戏管理页的编辑弹框里用「上传攻略 ZIP」上传。包整个套一层顶层目录会自动剥掉
（右键「压缩」出来的包必然是这种形态）。
它没有清单表、也不落库，「有没有攻略」由 `guide.zip` 在不在现算；查看时才把包解到运行时根
（`game/{游戏类型}/{卡带ID}/guide/`，下次直接复用），读取走 `GET /api/games/{id}/guide/{路径}`
（**需登录**），在游戏中心右键「攻略」用新标签页顶层打开。

本技能把**网上现成的静态 HTML 攻略站**变成这样一个目录。做法来自一次真实转换：
`https://www.imasaragame.com/yugiohmcgb/`（日文，GBC《游戏王 怪兽胶囊》）→ 本机
`/home/zf/code/test/guide`（438 个文件、2.9MB、174 个页面）。成品长这样：

```
guide/                 ← 成品目录（打包后就是 zip 的根）
├── index.html         ← 必须有；目录页 + 游戏资料表 + 出处
├── pages/             ← 原站的内容页，保留原站子目录层级（c/1.html、d1/1.html、mc/001.html…）
└── assets/
    ├── css/site.css   ← 原站多个样式表合并、删掉用不到的规则
    ├── fonts/         ← 图标字体（原样拷贝）
    └── images/        ← 原站的图片目录，按原站子目录分目录
```

三条原则，冲突时按这个顺序取舍：

1. **只留攻略本身**——广告、脚本、站内搜索、站点级导航、版权页脚、外链全部删掉。
2. **页面风格跟原页一致**——保留原站的 DOM 结构与 class、照搬它的样式表，不要重新设计版式。
3. **正文转中文，专有名词保留原文**——只在**标题/词条位置**写 `中文（原文）`
   （`装甲蜥蜴（アーマーリザード）`），正文与数据表格里只写中文 `装甲蜥蜴`。

抓之前先看原站的版权声明（上面那个范例站写明「無断転載を禁じます」）。本技能是给**个人自用**的：
只往自己的平台上放，**首页 footer 必须写出处**。

## 平台侧的硬约束（导入前逐条核对）

| 约束 | 值 | 越界会怎样 |
|---|---|---|
| 入口 | **根目录**的 `index.html`（大小写不敏感，落盘统一小写；`index.htm` 不认，子目录里的不算） | 400「攻略根目录需包含 index.html。」 |
| 条目数 | 解压后 ≤ 2000（与 H5 共用 `archive.MAX_ENTRIES`） | 400 |
| zip 本体 | ≤ 128MB（Docker 路线 nginx `client_max_body_size 128m` 也卡这个数） | 400 / 413 |
| 单个文件 | 解压后 ≤ 64MB | 400 |
| 总体积 | 解压后 ≤ 256MB | 400 |
| 压缩比 | > 200 且解压后 > 1MB 视为异常 | 400 |
| 路径 | 禁 `\`、`?`、`#`、`%`、控制字符、`:*?"<>|`、绝对路径、`.`/`..` 段、以点或空格结尾的段、Windows 保留设备名（`CON`/`NUL`/`COM1`…）；相对路径 ≤ 512 字符、≤ 32 段 | 400 |
| 重名 | 大小写不敏感（`Index.html` 与 `index.html` 冲突） | 400 |
| 链接 | **一律相对路径**。攻略在 `/api/games/{id}/guide/` 前缀下顶层打开，`/xxx` 这种绝对路径会指到站点根、必然 404 | 页面 404/白屏 |

**导入**：把成品目录打成 zip（Windows：右键 `guide` 文件夹 → 压缩；命令行：
`cd <父目录> && zip -r guide.zip guide`）→ 游戏管理页 → 该游戏「编辑」→
「游戏攻略」→「上传攻略 ZIP」→ 保存（重传整体替换旧攻略）。
**打断言**：`python .claude/skills/make-guide/check_guide.py <目录>` 先跑一遍，
它校验的是解压后的目录，打包前后都适用。
**验证**：游戏中心右键卡片 →「攻略」（**没有攻略就不显示这一项**）→ 新标签页打开，
点几个内部链接、看图片和样式。

## 流程

1. **定游戏与标题。** 拿到卡带ID、游戏类型、游戏中文名；攻略标题统一 `【攻略】<游戏中文名>`。
2. **找原站。** 搜「<游戏名> 攻略 / walkthrough / 攻略チャート」。合格标准：正文是**静态 HTML**
   （不是 JS 渲染出来的）、有目录或分页、结构清晰（分层导航 + 表格 + 图片）。
3. **完整镜像。** `wget --mirror --page-requisites --convert-links` 或逐页 `curl`，
   图片/CSS/字体一并抓；控制频率、看 robots.txt。**记下出处 URL**（首页要用）。
4. **目录规划。** 按开篇那个结构摆：根只留 `index.html`，原站内容页整棵收进 `pages/`，
   图片/CSS/字体收进 `assets/images|css|fonts/`。原站子目录层级照搬，别拍平（免得同名文件打架）。
5. **剥站点外壳。** 照下面的对照表删。
6. **重写链接。** 所有 `href`/`src` 改成**按当前文件深度正确的相对路径**：`pages/mc/x.html` 里指向
   `pages/c/1.html` 要写 `../c/1.html`，`pages/x.html` 里写 `c/1.html`，根 `index.html` 里写
   `pages/c/1.html`。原站侧栏里那种 `/yugiohmcgb/c/1.html` 绝对链接**必须改**。改完逐个点一遍。
7. **翻译。** 先列**术语表**（怪物名/道具名/地名/系统词，原文与中文对照）——**写在 guide 目录之外**
   （如 `/tmp/<游戏>-术语表.md`），目录里每个文件都占条目数的上限。然后逐页翻，术语表照着填。
8. **补外壳。** `<html lang="zh-CN">`、charset、viewport、`<title>`（见下）、首页 footer 写出处。
9. **自检。** `python3 .claude/skills/make-guide/check_guide.py <攻略目录>`：error 清零、
   warning 逐条确认。
10. **精简（视情况，见下节）。** 同类详情页逐页重复同一份大纲索引时，只留 `index.html` 那一份，
    详情页删掉冗余块。
11. **导入并验证**（见上面的导入步骤）。

### 精简：详情页里重复的大纲索引

翻译完先别急着打包，看一眼详情页——这类站常把「整站/整类目大纲」复制进每一页的正文，
几十上百个详情页各扛一份，是体积的主要来源，也纯属导航冗余。**判据、做法和边界如下，
不满足就别动**（脚本不检查这一类冗余，得人工判断）。

**什么时候精简**

- 同一类的详情页里，正文区有一整块**纯跳转清单**（`<ul>`/`<ol>`/表格/`<nav>`），
  列出大量其它页面的链接，且这份清单在**多数同类页面**上逐字重复
  （典型：每只宝可梦的详情页都带着整份图鉴大纲；每张卡的页面都带着整份卡表链接）。
- 它与 `index.html` 或某个公共索引页的大纲基本重合，删掉不影响读懂这一页。
- 数量级上才值得做：清单被复制了几十个页面。只有一两页重复、或精简后省不下多少，就别改。

**怎么删**

- **`index.html` 是保留大纲索引的地方**。原站另有专门承担索引的公共页（如 `pages/list.html`）时，
  那一页也留着——它自己就是大纲；除此之外的详情页一律只留本页内容。
- 详情页把那一整块**连容器一起删**（`<ul>` 连同它前面的小标题、外层 `<div>`/`<section>`），
  **别留空壳**；容器在 CSS 里有专用样式且只服务这一块的，可选一并删掉规则。
- 只删**跳转清单**：正文、表格、图片、本页自己的数据与说明文字一律保留。清单里若混着本页专属
  信息（条目数值、说明列），这一块就不算冗余，**整块留下**。拿不准时按「不删」处理。
- 删完重跑 `check_guide.py`：error 必须照旧为 0（重点看断链），再抽 2–3 个详情页打开确认版式没塌。
- 把精简前后的**页数 / 文件数 / 体积**记进进度文件的一节「精简」；不满足条件就写一句
  「无重复索引，未精简」。

**边界：这些不算冗余，别顺手删**

- 侧栏的攻略内导航（`#accordion` 之类每页都有的章节入口）——它是站内导航骨架，本技能要求每页都有；
  只有它被扩成整站全量条目清单时，才按上面的判据处理。
- 面包屑、页脚的上一页/下一页、详情页里的前后篇链接、首页 `index.html` 自己的大纲。
- 平台要求保留的内容结构（表格、图片、`section` 层次）不在精简范围内。

### 保留 / 删除对照表

| 原站的东西 | 怎么处理 |
|---|---|
| `<script>`（jQuery、统计、广告） | **全删**。范例成品里一个 script 都没有 |
| 广告位（`<ins class="adsbygoogle">`、`.adspace`） | 删 |
| 站内搜索框（`<form id="search-box">`） | 删 |
| Amazon 推荐 `<iframe>`、任何 `<form>` | 删 |
| 站点级侧栏菜单（关于本站/链接集/邮件表单等外链） | 删，整段 `<ul>` 一起删，**别留空壳** |
| 页脚站点声明、Copyright 行、返回顶部、语言切换 | 删 |
| 页脚「回总站首页」（`tohome`） | 删 |
| 一切外链（`http(s)://`、`//`） | 删，或退化成纯文本；攻略里不该有外链 |
| 内容结构 `article/#main/#content/#inner/section/h1–h4/表格/图片` | **原样保留**，class 也保留 |
| 面包屑 `#bread` | 保留并翻译（`ホーム` → `首页`） |
| 页脚上一页/下一页导航 | 保留并翻译 |
| 侧栏里的攻略内导航（各章节入口） | 保留并翻译；**每页都要有**，链接按深度改写（它被扩成整站全量条目清单时，按后面「精简」一节处理） |
| 详情页正文里重复的大纲索引（每页都抄一份整类目/整站链接） | `index.html` 留一份，详情页**连容器删掉**——见「精简：详情页里重复的大纲索引」 |
| header 的 logo 图片链接 | 换成文字标题链接 `【攻略】<游戏中文名>` |
| 图片 | 原样拷贝，不重采样、不改格式、不压缩，只改路径；`alt` 一并翻译 |
| 样式表 | 原站多个 CSS 合并成一个 `assets/css/site.css`，删掉上面被删元素的选择器；字体栈换中文优先 |

### `<title>` 规则

- 首页：`【攻略】游戏王：怪兽胶囊`
- 子页：`<页名> - 【攻略】游戏王：怪兽胶囊`
- 列表/详情页带中间层：`装甲蜥蜴（アーマーリザード） - 怪兽胶囊一览 - 【攻略】游戏王：怪兽胶囊`

### 翻译时原样保留的东西

数字、等级、概率、表格结构一律不动；`Game Over`、`HP/AT/DF/SP`、`LV`、键位名，
以及本来就是英文/片假名的专有名词（按术语表定名，别半译）。

## 常见坑（都在这份范例成品里真出现过）

- **`<meta name="description">` 整份留着原语言**——范例 174 个页面全是日文。它也算可见文本
  （搜索结果、分享预览），必须一起翻。
- **复合词半译**——`隠しカプセルマシン` 被译成 `隠し胶囊机`（4 个文件）。术语表要收**复合词**，
  不能只收单词。
- **`alt` 没翻**——`alt="ザンキ"` 留了 2 处。`alt`、`title` 属性都算可见文本。
- **留空壳容器**——首页侧栏删完菜单后剩了个 `<aside class="side">` 套空 `<ul></ul>`。删就删干净。
- **CSS 里留外文和死规则**——范例 `site.css` 还留着 `content: "▼クリックで等倍表示"` 与
  `#help-popup`/`#copyright` 这些用不到的规则；字体栈也还是 `Yu Gothic/メイリオ`。
- **图片多的站会撞 2000 条目的上限**——只留攻略真正用得到的图（这本来就是原则一）。

## 用法

```bash
python3 .claude/skills/make-guide/check_guide.py [攻略目录] [--quiet]
```

- `<攻略目录>`：要交付的攻略根目录（含 `index.html` 那一层），默认当前目录。
- `--quiet`：只打印结论与 error，不列 warning 明细。

输出是中文报告，分「错误 / 警告 / 统计」三段；**有 error 时退出码 1**，只有 warning 时退出码 0。
它只读，不写任何文件，可以随便反复跑。

## 依赖

只用 Python 标准库（`html.parser` + `pathlib`），**不引入任何第三方包**，也**不在**
`requirements.txt` 里（后端运行不需要它）。

## 排错

- **脚本报 error**：先修 error（平台会直接拒），再看 warning。error 分三类——外壳没剥干净
  （script/iframe/form/外链/绝对链接）、路径或数量越界、页面本身坏了（断链、缺 charset、`lang` 不对）。
- **导入报 400**：对照上面「硬约束」表，中文消息会指出是哪条（缺 `index.html`、重名、路径非法、超限）。
- **导入成功但打开是空白/没样式**：多半是绝对链接或漏抓资源——脚本的断链与绝对链接检查就是查这个。
- **右键菜单里没有「攻略」**：`has_guide` 跟磁盘走，说明数据根下的 `guide.zip` 没写成功
  （没上传、或上传被拒）。
- **打开攻略 400**：包在数据根里但解不开（被手改坏了、或不是合法 zip），后端会再校验一次。
- **中文显示怪/字形不对**：CSS 字体栈还在用日文字体，换成中文优先
  （`"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`）。

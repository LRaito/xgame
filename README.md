# XGAME

个人自托管的**游戏平台**：把 Flash、HTML5 与 8/16-bit 主机游戏收进一个网页，浏览器打开就能玩，
存档、截图、攻略与游玩进度都跟着账号走。

> 这份 README 是**使用指南**，从「怎么跑起来」讲到「怎么玩」，面向用这个站点的人。
> 要改代码、看架构与数据字典，见 [`DEVELOP.md`](DEVELOP.md)。

## 快速开始

### 1. 设置存储根目录

游戏本体、封面、H5 资源、攻略、存档、截图，以及 SQLite 库，全都放在**一个数据根目录**里
（容器把它挂到 `/data`）。**这个目录就是整个平台的全部数据，要备份的话直接备份它一个即可。**
默认是仓库下的 `./data/storage`，**建议改到仓库外面**：放在仓库里会被 `git pull` 覆盖，
而且这个路径必须在 Docker 启动之前就可达。

**更推荐放在 Windows 主机的磁盘上、挂到 WSL 下使用**，例如 `STORAGE_HOST_DIR=/mnt/x/xgame`。
这样整个数据目录就是一个普通的 Windows 文件夹，可以直接扔进百度网盘的「文件夹备份」，
用上它免费的一键备份——存档、截图这些丢了就找不回来的数据尤其值得这么放。
（备份时会报 SQLite 文件复制失败，不用管，原因见「常见问题」。）

```bash
cp .env.example .env
# 编辑 .env：
#   STORAGE_HOST_DIR=/mnt/x/xgame    ← 数据放这儿，换成你自己的路径
#   WEB_HTTPS_PORT=443               ← 对外端口，不想改就留默认
```

两个值都可以不管：不建 `.env` 时 compose 会退到默认值（`./data/storage` 与 443）。

### 2. 一键编译和部署

```bash
make all        # = docker compose build && docker compose up -d
```

首次构建需要联网（要从上游拉 Ruffle 与 EmulatorJS 的引擎资产），之后就都在本地了。
HTTPS 证书已经随仓库提供，不用另外生成。更细的部署说明（换证书、换端口、排障）见 [`DEVELOP.md`](DEVELOP.md)。

### 3. 打开站点

站点默认跑在 **https://localhost** 或 **https://127.0.0.1**——两者是同一个站点，用哪个都行。
默认端口是 443，所以地址里不用写端口；**端口可以配置**，换过之后就是 `https://localhost:<端口>`。

**只支持 HTTPS**：80 端口没有开，`http://` 打不开。

## 注册与登录

没有游客模式，除了注册和登录，所有页面都要登录。

在登录框下方点「注册一个」，填用户名（数字、字母、中划线、下划线，2–32 个字符）和密码，
**注册成功即登录**。连续输错密码会被临时锁定，等几分钟再试。

账号只用来隔离每个人的**模拟器配置、键位与存档 / 截图**，不涉及任何权限。

## 界面怎么用

首页就是**游戏中心**（`/` 会自动跳到 `/games`）。左侧栏只有「游戏中心」与「游戏管理」两项。

侧栏与播放页的标题栏平时都是**收起的**：鼠标移到屏幕左边缘滑出侧栏，移到页面顶部滑出播放页标题栏
（全屏时也一样）。它们盖在页面上，不占地方、也不会把游戏画面挤小。

## 游戏中心

站点首页就是游戏中心。

**找游戏** — 工具条上可以按「进度」「类型」筛选，也能按名称搜索。「全部游戏」先按游戏类型分组，
组内再按卡带版本（默认 / 日版 / 美版）分小块，上面还有一行「最近游玩」。
（目前只有 FC 的日版、美版会分开摆。）

**卡片上有什么** — 封面、名称，以及一行进度标签 + 总游玩时长。进度是「未开始」时这一行整行不显示。

**在卡片上点右键**（卡片以外的地方还是浏览器原生菜单）：

| 菜单项 | 作用 |
| --- | --- |
| 详情 | 打开详情弹框 |
| 攻略 | 在新标签页打开这盘游戏的攻略（这盘游戏没有攻略就不显示这一项） |
| 设置进度 | 未开始 / 进行中 / 已通关 |
| 设置时长 | 手动改总游玩时长（小时）；保存后从该数值继续累加 |

进度**不会**因为玩过就自动变，只能在这里手动改；时长则在游玩时自动累加。

**点一下卡片**就进播放页开始玩。

## 玩游戏

三种游戏三种玩法，都是点开即玩、不装插件：

- **Flash（`.swf`）** — 用 Ruffle 运行时跑。
- **HTML5（`.zip`）** — 解包后在沙箱里跑，等同于一个网页游戏。
- **主机（NES / SNES / GB / GBC / GBA / MD / GG / SMS）** — EmulatorJS 在浏览器里跑模拟器，
  引擎随站点一起部署，运行时不需要外网。

### 播放页

标题栏（鼠标靠到页面顶部才滑出）右侧是「全屏」和「返回游戏中心」；左侧按钮自左向右是
「截图」「保存配置」「窗口倍率」「显示游戏机」（只有 GBA / FC / GBC 有）、「存档管理」。

- **保存配置** — 键位、模拟器选项、金手指按平台存在账号里，进游戏时会自动写回本地；改完点这个按钮上传。
- **窗口倍率** — 弹出两列矩阵：行是 `1×`–`4×`（含 .5 档）与「适应窗口」，列是显示比例。
  默认「像素完美」；FC 还多一列「4:3」，是真机 CRT 的观感。
- **显示游戏机** — 把 GBA / FC / GBC 的机身图盖在画面上，只从屏幕洞里露出游戏画面；再点一次收起。
- **存档管理** — 见下面「存档」。

**快捷键**

| 按键 | 作用 |
| --- | --- |
| `Ctrl+Shift+S` | 截图（与标题栏的「截图」按钮同效） |
| `回车` | 载入本地存档（没有本地存档时，这一下照常交给游戏，等于主机的 Start 键） |

## 存档

### 本地存档（存在这台机器的浏览器里）

- **主机（模拟器）** — 每盘游戏只有一份本地档，内容就是「即时存档」；捕捉、导入、云端还原都是**覆盖**它。
  引擎自带的存档槽与游戏原生存档是另一回事，平台不备份它们（四种存档的区别见「常见问题」里的对照表）。
- **Flash** — 就是 `.sol` 存档文件，可以有好几份。**得先在游戏里存过档**才能捕捉到；捕捉之后游戏会重启
  （Ruffle 只有在被卸载时才落盘），属正常现象。
- 两者都在「存档管理」里操作：捕捉当前进度、导入本地文件、下载到磁盘、删除。
- **HTML5 游戏没有存档**（沙箱里拿不到浏览器的本地存储）；**大部分 Flash 游戏也没有落盘存档**——
  进度只在内存里，关掉页面就没了。
- 本地档只存在**这台浏览器**里：换设备、换浏览器、清了站点数据都会没有，想跨设备就用下面的云端存档。

### 云端存档（跟着账号走）

在「存档管理」里把**此刻的全部本地存档**整包存成一份快照传到服务器，换设备、换浏览器、清了缓存都能还原。
列表里每份快照都能载入、改名、删除；「同步至云端」就是把当前进度再存一份新快照。

> 在游戏管理页删掉一盘游戏时，它在**所有账号**上的云端存档与截图都会被一起删掉。

## 截图（主机游戏）

按 `Ctrl+Shift+S` 或点标题栏的「截图」按钮，会截下当前画面并弹出确认框：左边是正方形预览，
右边可以填一句描述（≤15 字），点「确认」才存进**你自己的**截图图库，点取消就丢掉。

看和管理截图有两个入口：

- **详情弹框顶部的图片栏** — 一行 4 个正方形格子，第一格永远是封面，后面依次是这盘游戏的
  **图集**（见下一节）和**你自己的截图**，格子下方居中显示描述。按钮和鼠标滚轮都能左右翻页。
- **详情弹框右栏的「截图 [管理]」** — 相册式平铺的截图管理页：可以上传本地图片、单击描述就地修改
  （回车或点空白保存、`ESC` 放弃）、按住整块拖动排序、点右上角「删除」进多选删除。

截图按账号隔离，只有本人看得到、改得动；封面则是大家共享的。

## 图集

图集是**一个游戏一套的展示图**——宣传图、说明书扫描件之类，和截图正好相反：**按游戏共享**，
不记是谁传的，谁都能看、能传、能改描述、能删、能拖动排序。

- **在哪看** — 详情弹框顶部的图片栏，排在封面之后、你的截图之前。
- **在哪管** — 游戏管理页点「编辑」，弹框里的「图集 → 管理」，打开的是和截图管理同一套相册界面
  （上传本地图片、单击描述就地改、按住整块拖动排序、多选删除）。新建游戏的弹框里没有这一项，
  因为那时还没有卡带目录可以放图。

## 攻略

攻略是**整份文件夹**上传的静态网页，入口固定是文件夹根目录的 `index.html`。
有攻略的游戏，卡片右键菜单里会多一项「攻略」，点开在新标签页里打开——所以攻略里的子页面、
图片、CSS 都能正常互相跳转。

## 游戏管理

「游戏管理」页负责把游戏搬进来，以及改元数据。

每盘游戏有一个**卡带 ID**：添加时必填、全局唯一、**建好之后不能改**，它同时是磁盘上的目录名，
所以改游戏名不会挪动任何文件。要换卡带 ID 只能删掉重建。

### 添加游戏

| 方式 | 说明 |
| --- | --- |
| 本地上传 | 选本体文件（可同时选封面）。**游戏类型按文件后缀自动判定**，不用手选 |
| 网络上传 | 填 http/https 直链，服务端下载后入库（上限 512MB） |
| 搬运 | 填 7k7k / 4399 / flash.homes 的游戏页地址，服务端解析并下载 |

本体支持的后缀：

| 后缀 | 游戏类型 |
| --- | --- |
| `.swf` | Flash |
| `.zip` | HTML5（压缩包根目录要有 `index.html`） |
| `.nes` / `.sfc` `.smc` | FC / SNES |
| `.gb` `.gbc` / `.gba` | GB / GBA |
| `.md` `.gen` / `.gg` / `.sms` | MD / GG / SMS |

### 元数据

- **卡带类型**（卡带版本）— 默认 / 日版 / 美版，用国旗单选。目前只有 FC 区分日版美版，其余只有「默认」。
- **封面** — 可以单独上传或换掉。游戏中心卡片按类型渲染封面（Flash 画成实体光盘、GB/GBC 把封面
  合成进一整张卡带、其余就是普通封面）。
- **名称** — 同一游戏类型下不能重名，且必须是合法的 Windows 与百度网盘文件名。
- **换本体** — 换了本体就跟着换游戏类型（如 `.swf` 换成 `.nes`）。第一次上传后会记住本体的 CRC32，
  之后换本体只接受同一个文件，防止误覆盖。
- **攻略** — 在编辑弹框里「上传攻略」选一个文件夹整体上传（重传即整体替换）。

列表里每行有**详情**、**编辑**、**删除**。

**删除**会连磁盘上的游戏文件、以及**所有账号**在这盘游戏上的云端存档和截图一起清掉，
所以要**手打一遍卡带 ID** 才能确认。删之前想清楚。

## 常见问题

**浏览器说证书不安全？** 自签名证书的正常现象，三种应对：

- 点「高级 → 继续访问」—— 最省事，但换个浏览器、或者清了站点数据，就得再来一遍。
- **把证书下载到本机、导入浏览器** —— 拿到站点的证书文件（仓库里的 `certs/cert.pem`，或直接找管理员要），
  在浏览器的证书管理里导入到「受信任的根证书颁发机构」，之后访问这个站点就是绿锁、不再报警。
- 换一张受信任的证书（怎么换见 [`DEVELOP.md`](DEVELOP.md)）。

**页面打不开、一直转圈？** 确认地址是 `https://` 开头（不支持 HTTP，也没开 80 端口），端口对不对。

**存档存不上、或者存档丢了？** 先看你要存的是哪一种——这个站上一共有四种存档：

| 存档 | 是什么 | 存在哪 | 换设备 / 清缓存后还在吗 |
| --- | --- | --- | --- |
| 模拟器即时存档 | 模拟器引擎自带的存档槽（引擎菜单里的「存档 / 读档」），把这一刻整机状态冻住 | 浏览器里，引擎自己的存储 | 不在。想留底就「捕捉当前进度」，把它变成平台的本地存档 |
| 模拟器原生存档 | 游戏自己的存档（电池存档 / SRAM）——RPG 里在游戏菜单中存的通常是这一种 | 浏览器里，引擎自己的存储 | 不在。平台不备份它；要留底就先进游戏，再「捕捉当前进度」 |
| 本地存档 | 平台「存档管理」里的那一份：主机是上面那份即时存档的拷贝，Flash 是 `.sol` 文件 | 浏览器里，平台自己的存储 | 不在（但可以「下载」到磁盘留底） |
| 云端存档 | 把本地存档整包存到服务器 | 服务器，按账号 | **在**。换设备、换浏览器、清了缓存都能载入还原 |

前两种归模拟器引擎自己管，平台碰不到；平台能备份、能同步的只有后两种。

**为什么有的游戏存不了？** **HTML5 和大部分 Flash 游戏本身就没有「落盘存档」这个功能**——
它们把进度放在内存里（比如魔塔这类游戏），关掉页面就没了，自然也无从捕捉、下载或同步到云端。

**Flash 游戏要怎么存？** 得**先在游戏里存一次档**（用游戏自己的存档功能），之后在「存档管理」里点
「捕捉当前进度」才能抓到 `.sol` 文件。另外，**捕捉之后游戏一定会重启**——Ruffle 只有在被卸载时才会把
最新进度写回本地存储，所以平台只能停掉播放器落盘、写完档再重新加载游戏。这是模拟器（Ruffle）的限制，
不是出错，重启完接着玩就行。

**换了台电脑，键位全变了？** 进游戏时会自动写回账号里的配置；改完记得点「保存配置」上传。

**找不到「显示游戏机」？** 只有 GBA / FC / GBC 有机身图。

**截图截出来全黑？** 极少数浏览器拷贝画面时会拿到全黑的一帧，换一个浏览器试试。

**某盘游戏的「攻略」菜单项不见了？** 攻略是磁盘上的一个文件夹，被删掉或挪走，入口就跟着消失。

**别人看不到我的截图？** 本来就看不到——截图按账号隔离，只有本人可见可改。

**用百度网盘备份数据目录，报「SQLite 文件复制失败 / 文件被占用」？** **直接无视即可。**
`app.db` 是 SQLite 库，在 WSL 里跑着的后台服务一直开着它；数据目录又是挂在 WSL 下的 Windows 盘
（`/mnt/x/…`），Windows 侧的百度网盘就拷不动这个被占用的文件，所以备份任务会报这么一条错。

不影响备份的意义：服务每个月会自动往同一个目录（`db/`）备一份 `<年>-<月>.db`，那份写完就不再动，
百度网盘能正常备份走，所以元数据其实一直有兜底。真想拷一份最新的 `app.db`，就先停掉服务再拷：

```bash
docker compose stop api     # 拷完再 docker compose start api
```

1. **一键搬运只覆盖 Flash 游戏。** 三个站点的解析（7k7k / 4399 / flash.homes）都是冲着 Flash 做的
   （4399 有少量页面会落到 H5 入口），主机 ROM 与其他类型完全搬不了，只能走本地上传或网络上传。
   后续补全其他游戏类型与站点。

2. **模拟器配置要手动保存。** 键位、模拟器选项、金手指改完之后，必须点标题栏的「保存配置」才会存进
   账号里，容易忘（进游戏时倒是会自动写回）。后续改成自动保存。

3. **GBC 与 GBA 的封面画法不统一。** 卡片封面按游戏类型分支渲染：GB/GBC 有整张卡带素材
   （`gbc-cart.png`），封面要按贴纸窗的像素几何合成进去；GBA 没有对应的卡带素材，只能落到
   「普通封面」那条分支，于是两者的观感与代码路径都不一样。后续给 GBA 补一张卡带素材，
   统一成同一套画法。

4. **百度网盘备份会报 SQLite 文件复制失败。** 数据目录挂在 WSL 下的 Windows 盘（`/mnt/x/…`）时，
   在 WSL 里跑的 api 一直占用着 `app.db`，Windows 侧的百度网盘拷不动它，备份任务就会报错。
   目前不影响备份功能直接无视即可（额外会有一个每月的 SQLite 备份 `<年>-<月>.db` 是静态文件，能被正常备份走），后续改进。

5. **只实测了部分游戏类型。** 亲手跑通的是 Flash、FC、GBC、GBA 四类；HTML5、SNES、MD、GG、SMS
   还没实测过（GB 与 GBC 在项目里是同一个游戏类型、走同一条路）。后续逐个验证。
